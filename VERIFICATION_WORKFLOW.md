# Проверка промежуточной модели

## Переход к основному источнику TIFF

`--prepare-tiff-revision <file.SLDPRT>` принимает только побайтно проверенную базу Ø19, создаёт отдельную уникальную WIP-копию и открывает её с диска для чтения дерева операций. Сверяет исходник/копию до и после, пишет `tiff-revision-inventory.json`. Это начало рабочей ревизии, **не изменение геометрии и не проверка соответствия TIFF**. Старые режимы построения и аудита относятся к исторической PDF-базе; в аудите явно указан `TiffConformanceAssessed=false`.

## Безопасный запуск

Запуск `dotnet run --project CadTest` без аргументов, а также `--help`/`-h` выводит справку и завершает работу без подключения к SolidWorks и записи файлов приложением. Историческая база stage16 с Ø15 строится только явно: `dotnet run --project CadTest -- --build-legacy-stage16`. Она не заменяет текущую исправленную деталь Ø19. Режим `--trial-full-spline` тоже использует историческую базу и выводит предупреждение.

Для текущей модели используйте режимы Ø19 ниже; путь к актуальному SLDPRT указан в `CURRENT_MODEL.md`. Обычный запуск не открывает и не перестраивает этот файл автоматически.

После сборки `scripts/test_safe_cli.ps1` проверяет реальные запуски без аргументов, с `--help`/`-h` и неизвестным параметром. Проверяется код завершения, ожидаемый текст и неизменность состава, размеров и времён записи файлов `output`. Это тест маршрутизации CLI, не побайтовая проверка CAD; запускать без параллельной записи результатов в `output`.

## Исправленный массив Ø19

`--correct-flange19-from <file>` создаёт отдельную ветку с12×Ø19, проверяет снятие объёма и прежнюю геометрию перед сохранением. `--verify-saved-d19 <file>` запускает полный контроль этой ветки после свежего открытия. Более узкий `--verify-saved-d19-focused <file>` проверяет только12 цилиндров Ø19, их центры/торцы и общий объём против одноимённого отчёта построения, со сверкой хешей. Его `focused-verification.json` явно содержит `FullInheritedGeometryRecheckedAfterReload=false` и не заменяет полный повторный контроль.

Аудитор `--audit-drawing-conformance` теперь принимает оба вида отчётов, но сохраняет различие объёма проверок. Для целевого отчёта обязательны12 цилиндровØ19, совпадение объёмов, неизменный SHA256 отчёта построения, совпадение пути модели и признаки выполненных проверок базы/шлицев до сохранения. Хеши модели и обоих отчётов сверяются до/после аудита. Результат не объявляет полный контроль после открытия. `VerificationEvidence` содержит7 отрицательных сценариев; включён в `--self-test`.

## Экспериментальные Д/К и подготовка КГ

`--verify-saved-approx-dk <file.SLDPRT>` открывает новую побайтно идентичную копию (предупреждения открытия должны быть 0). Проверяются составная чаша Д/К, её границы X246,5…260 и соединение с Ø12, оба конуса подготовки КГ и переходы Ø8 от t7 до t9; далее подводы, M90, обе M8/M12, конусы Ø6, каналы, корпус и шлицы. Проверка прежнего выходного ребра Ø12 на X260 заменена проверкой фактической общей кромки с чашей; вход X245 сохраняется. Исходник и проверочная копия не сохраняются, их SHA256 должны остаться неизменными. Итоговый `verification.json` появляется только после полного успеха.

Режим предназначен именно для согласованной экспериментальной ветки. Он не подтверждает трактовку базы Д/К по чертежу, резьбу КГ (её нет) или производственную готовность. Проверка номинальной M90 без Д/К не является заменой этому режиму. Не запускать два CAD-режима одновременно.

Построение выполняется последовательно: `--trial-kg-prep-from <M90.SLDPRT>`, затем `--trial-dk-from <KGPrep.SLDPRT>`. Каждый шаг создаёт отдельную WIP-копию и сохраняет итоговый файл только после предусмотренных проверок; WIP не является готовым результатом. Расчётные самопроверки доступны через `--self-test` без SolidWorks.

## Сохранённая ветка с M90

`--verify-saved-m90-trial <file.SLDPRT>` включает весь контроль ветки M8 и отдельную проверку M90. Проверяется не только название операции: фактический профиль `Metric Die / M16x2.0`, переопределение диаметра винтовой линии 90 мм, шаг 2 мм, длина винтовой линии 33 мм, направление/нарезка/ограничения, отсутствие ошибок и пространственные границы. Для выбранной библиотечной операции винтовая линия заканчивается X38, а край выреза — X39,75; это явно отражено в отчёте. Длина полного профиля, сбег и 6g не принимаются.

`--thread-library-sizes` читает конфигурации штатной библиотеки без её изменения. Не следует передавать приблизительные имена: `M16x2` и `M16x2.0` API обрабатывает по-разному. Перед построением наличие точного имени проверяется программно.

## Сохранённая ветка с M8

`--verify-saved-m8-trial <file.SLDPRT>` выполняет свежую загрузку побайтно идентичной копии, проверку неизменности SHA256 и весь контроль ветки Ø6,8 ниже. Дополнительно проверяются обе M8: ровно одна операция на ветвь, ошибки/предупреждения, номинальный размер и шаг, правая однозаходная нарезка, направление, ограничения начала/конца и пространственный диапазон S=0…6/cos(4°) с точностью 0,0001 мм. Плоские грани пересечения с исходным Ø6,3 отделены от собственно резьбовых поверхностей. Допуск 6H, герметичность и выбранная длина по чертежу этим не подтверждаются.

Поле `M8` записывается в `verification.json` только после завершения всего контроля. Запуск одного лишь старого режима конусов не заменяет эту проверку.

## Сохранённая ветка с боковыми Ø6,8

```powershell
dotnet run --project CadTest -- --verify-saved-feed-trial CadTest/output/Tsapfa_TRIAL_RearFeeds_20260925_091752_552.SLDPRT
```

Как и проверка конусов ниже, режим создаёт и загружает отдельную побайтно идентичную копию, требует нулевых предупреждений открытия и проверяет неизменность обоих файлов по SHA-256. Дополнительно проверяются операции Ø6,8: отсутствие ошибок/предупреждений, диаметр, положение и направление оси, общие кромки с продольным Ø6,3. Теперь проверяется также ось смежного Ø6,3, а не только его радиус. Общий проверяющий метод используется и при новом построении, и после повторной загрузки.

В отчёте поле `RearFeeds` содержит результаты боковых ветвей. Прежний `--verify-saved-cone-trial` не заменяет этот режим: он не проверяет Ø6,8. Проверка соединения не определяет минимальное проходное сечение и не подтверждает герметичность или соответствие пробных баз чертежу.

## Повторная загрузка сохранённого варианта с конусами

```powershell
dotnet run --project CadTest -- --verify-saved-cone-trial CadTest/output/Tsapfa_TRIAL_EntryCones_20260925_083117_656.SLDPRT
```

Режим создаёт побайтно идентичную копию в новом каталоге `CadTest/output/verification/<GUID>/`, проверяет SHA-256 до и после копирования, открывает её только для чтения и требует отсутствия предупреждений открытия. Уже открытый документ (128) не считается повторной загрузкой. Исходная модель и проверочная копия не сохраняются через CAD; обе контрольные суммы проверяются ещё раз после инспекции.

Проверяются конусы 45°/глубина 1 мм, оси и соединения каналов, базовые поверхности, шлицы и M12. Пустой набор граней входного элемента теперь приводит к ошибке, а не к ложному успеху. Точный независимый объём всего тела по-прежнему не проверяется; библиотечные резьбы и прочие ограничения TRIAL сохраняются. Проверка не подтверждает соответствие всему чертежу.

`verification.json` создаётся только после успешного завершения. Копия без отчёта — не признак успешной проверки. Проверочный каталог оставляется для воспроизводимости, его SLDPRT не является новой геометрической ревизией.

Для экспериментальных удлинённых каналов: `CHANNEL_TRIAL_REVIEW.md`, команда `--inspect-channel-connections <file>`. Режим отдельно проверяет оси цилиндров и их общие кромки, без изменения модели; весь объём и остальные элементы этим режимом не принимаются.

Для новой пробной копии с M12 используется `--inspect-m12-trial`, см. `M12_TRIAL_REVIEW.md`. Обычный `--inspect` проверяет объём основной базы и намеренно не подходит для моделей со шлицами/резьбами. В M12-режиме контролируются базовые поверхности, шлицы и номинальные резьбы, но точное независимое совпадение общего объёма не заявляется.

Текущая геометрия — stage16 (`FLANGE_HOLE_STAGE16.md`), включая отдельное Ø22 по Р–Р. Раздел проверки stage11 ниже исторический; текущий `--inspect` проверяет stage16, старые модели без Ø22 намеренно не пройдут. Проверка не закрывает Д/К и другие отсутствующие элементы.

## Команды

```powershell
dotnet run --project CadTest -- --self-test
dotnet run --project CadTest -- --inspect F:\Project\DrawingTo3D\CadTest\output\Tsapfa_stage16_20260924_190613_446.SLDPRT
```

Обычное построение без аргументов и `--inspect` теперь автоматически выполняют регрессионные тесты до подключения к SolidWorks. `--validate-only` остаётся быстрой проверкой параметров, без полного набора тестов и без CAD.

## Отчёт

После успешной проверки существующей модели либо проверки и сохранения новой создаётся отдельный JSON `имя_модели_acceptance_UTC_GUID.json`. При неуспешной проверке отчёт об успехе не создаётся. В отчёте:

- ревизия и проверяемый путь;
- контрольная сумма SHA-256 сохранённого файла;
- фактический и расчётный объёмы, абсолютное расхождение и допуск;
- временный X=245 с признаками согласования пользователем и отсутствия подтверждённого размера;
- ограничения и `IsManufacturingReady=false`.

Контрольная сумма идентифицирует байты файла. Геометрические проверки относятся к документу, открытому в SolidWorks. Если документ уже открыт, это не независимая повторная загрузка сохранённых байтов с диска; отчёт явно ограничивает область проверки. `--inspect` не сохраняет изменения в SLDPRT. Отчёт не подтверждает соответствие всему чертежу, материал, массу, незавершённые каналы, резьбы или Д/К.

Проверки тела охватывают число твёрдых тел, круговые рёбра, цилиндры, торы R2/R0,5, фланцевый ряд, местное Ø12, объём и ошибки операций верхнего уровня. Текущее `--inspect` сравнивает с текущей ревизией кода, а не автоматически определяет историческую ревизию файла.
